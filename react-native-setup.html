React Native · React devs

Setup from scratch.

Everything you need to go from zero to a running React Native project.

The right mindset

💡
You're not learning something new — you're learning a dialect. 80% of what you already know from React works exactly the same. What changes is the runtime, the primitive components, and how the app is bundled and run. Focus on the differences, not on starting over.

Required tools

01
Node.js — the same one you use for React
LTS version recommended (20.x or higher)

Check your current version:

node --version
npm --version
ℹ️
Node 18+ is fine. Use nvm (Mac/Linux) or nvm-windows to manage versions.
02
Expo CLI — your entry point
Expo is the recommended path to start. You don't need Xcode or Android Studio for your first project.
# No global install needed — use npx directly
npx create-expo-app --version  # verify it works
⚡
Why Expo and not bare React Native CLI: Expo handles the native build for you. For learning and for 90% of real projects, it's more than enough. You can eject later if you need to.
03
Expo Go — the app on your phone
See your app running without setting up simulators

Expo Go only supports a specific SDK version — don't download it from the App Store or Play Store directly. Instead:

  • Go to expo.dev/go — it shows the exact SDK version Expo Go currently supports
  • Download Expo Go from that page (it links to the right store listing)
  • Note the SDK number — you'll need it when creating your project
ℹ️
Your phone and laptop must be on the same WiFi network. Once running, scan the QR code the dev server generates and you're live.
⚠️
Expo Go doesn't support custom native modules — but it's more than enough to learn the fundamentals. See the Expo Go SDK matching section below to avoid the most common setup error.
04
Editor
Use whatever you're already comfortable with. One formatting tool to have:
  • Prettier — works exactly the same as on web

Expo Go SDK matching

⚠️
The most common setup error. Expo Go only runs projects built with a specific SDK version. If your project's SDK doesn't match, you'll get an "incompatible" error and the app won't load. The fix is to match them from the start — not after the fact.
01
Check which SDK Expo Go supports
Do this before creating your project

Go to expo.dev/go — it shows the SDK version the current Expo Go build supports (e.g. SDK 52). Write that number down.

ℹ️
This page also links directly to the App Store and Play Store listings, so download Expo Go from there rather than searching for it manually.
02
Create your project pinned to that SDK
Pass the exact SDK number from expo.dev/go
# Replace 52 with whatever SDK expo.dev/go shows
npx create-expo-app@sdk-52 my-app

This locks your project to the same SDK Expo Go expects. No mismatch, no error.

03
Already have a project with the wrong SDK?
Run expo-doctor to see what's off, then fix it
npx expo-doctor
# then fix mismatched dependencies
npx expo install --fix
04
If Expo Go still doesn't work — run on a simulator
No account needed, builds and runs locally

With Xcode (iOS) or Android Studio (Android) installed, skip Expo Go entirely:

npx expo run:ios
# or
npx expo run:android

This compiles the app locally and opens it in the simulator — no QR code, no version matching.

Simulators — optional but useful

📱
Expo Go on your phone is enough to get started. Simulators are useful for daily development but need extra setup. Install them when you're ready — here's the guide by platform.

iOS Simulator (macOS only)

  • Install Xcode from the Mac App Store (~7 GB, be patient)
  • Open Xcode → Settings → Components → Add platforms → download an iOS simulator
  • Accept the license: sudo xcodebuild -license accept
# Verify Xcode CLI tools are installed
xcode-select --install

Android Emulator on Mac

  • Install Android Studio
  • Android Studio → SDK Manager → install Android SDK Platform 33+
  • Create a Virtual Device (AVD) with API 33+
  • Add to your ~/.zshrc or ~/.bash_profile:
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$PATH:$ANDROID_HOME/emulator
export PATH=$PATH:$ANDROID_HOME/platform-tools

Android Emulator (Windows / Linux)

On Windows and Linux you can only run the Android emulator — iOS Simulator requires a Mac.

  • Install Android Studio
  • SDK Manager → Android 13 (API 33) or higher
  • Create an AVD (Android Virtual Device) with API 33+
  • Enable Hyper-V (Windows) or KVM (Linux) for better performance
⚠️
On Windows, add the Android SDK environment variables to your PATH via System Properties → Environment Variables.
# Verify adb is working
adb devices

Your first project

01
Create the project
Using Expo's default template
npx create-expo-app@latest my-first-app
cd my-first-app

This gives you a project with TypeScript, Expo Router, and a clean structure.

⚡
If you prefer plain JavaScript: npx create-expo-app@latest my-app --template blank
02
Run the dev server
Metro bundler starts up — it's the webpack of React Native
npx expo start

You'll see a QR code in the terminal. Open Expo Go on your phone and scan it. You can also press:

  • i — open iOS Simulator (Mac + Xcode only)
  • a — open Android Emulator
  • w — open in browser (not all components work on web)
03
Project structure
What you'll see and what matters
my-first-app/ ├── app/ ← your screens (when using Expo Router) │ ├── _layout.tsx ← root layout, like App.jsx in React │ └── index.tsx ← initial screen ├── components/ ← same as in React ├── assets/ ← images, fonts, etc. ├── app.json ← Expo config (name, icons, permissions) ├── package.json ← same as in React └── tsconfig.json

The quick translation map

React (web) React Native Status
useState, useEffect, hooks Exactly the same ✓ direct
Context, Redux, Zustand Exactly the same ✓ direct
fetch, axios, React Query Exactly the same ✓ direct
<div> <View> ≈ translate
<p>, <span>, <h1> <Text> ≈ translate
<img> <Image> ≈ translate
<input> <TextInput> ≈ translate
<button>, onClick <Pressable>, onPress ≈ translate
<ul> + map() <FlatList> ≈ learn
CSS / className StyleSheet.create() / style={{}} ≈ translate
React Router / Next.js React Navigation / Expo Router ≈ learn
window, document, localStorage Don't exist ✗ gone
CSS Grid Doesn't exist (Flexbox only) ✗ gone

What will surprise you

All text inside <Text>

You can't put loose text inside a View. Every string must live inside a Text component. No exceptions.

Flexbox defaults to column

On web, flex-direction defaults to row. In React Native it's column. A lot of your layouts will look off at first.

No style cascade

Styles don't inherit between components. Every Text needs its own typography styles.

iOS and Android diverge

Shadows, system fonts, keyboard behavior, and more work differently across platforms.

Debugging is different

No browser DevTools. Use Reactotron for a proper inspector, or the Expo logs. console.log still works in the terminal.

Hot reload is here

Fast Refresh works just as well (or better) as on web. Save the file and the change appears in seconds.

Tips

🌐
WiFi issues: Expo Go requires your phone and laptop to be on the same network. If the network has client isolation (very common in coworking spaces, universities, and hotels), use npx expo start --tunnel as a fallback. Requires installing @expo/ngrok.
📦
Always install packages through Expo: For packages with native modules, use npx expo install package-name instead of npm install. Expo resolves the compatible version automatically.

Verification checklist

  • ☐  node --version shows v18 or higher
  • ☐  Expo Go installed on your phone
  • ☐  You checked expo.dev/go and noted the SDK version
  • ☐  npx create-expo-app@sdk-52 test-app runs without errors (replace 52 with your SDK)
  • ☐  npx expo start shows the QR in the terminal
  • ☐  You can see the app running on your phone or simulator
  • ☐  You edit app/index.tsx and the change appears without reloading
✅
If all of these pass, you're ready to start building.
